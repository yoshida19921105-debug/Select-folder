# 商品設計 叩き台：Claude Code × muse で、スレッズ自動投稿とnote記事作成を仕組み化する

## 設計の原則（元投稿の要点。AIに毎回渡す）

1. お客さんに選ばせない。「AもBもCもあるので選んでください」は売れない。
2. 期間・コースで商品を分けない（3ヶ月/6ヶ月などの選択肢を作らない）。
3. 手段は1つに決めて言い切る。100%の人に正解である必要はない。例外に合わせて足すほど商品はぼやける。
4. やらなくていいことを先に決めてあげる（ダイエットの「運動はしない」と同じ）。
5. 不便さも体験の一部にする（星のや京都の「舟で行く」）。プロセスごと商品にする。
6. お客さんの権利は「Yes / No」だけ。選ぶ作業は我々が引き受ける。

## 前提

- テーマ：Claude CodeとmuseでスレッズとnoteのコンテンツをAI任せで回す。
- 使うツールは **Claude Code と muse の2つだけ**。発信先は **スレッズ（自動投稿）と note（記事）** に固定する。
- museの具体的な機能・操作は未確認。「museでやること」の欄は確認後に確定させる（仮置き）。
- 対象：発信で収益化したいが、毎日の投稿と記事作成が続かない人。AIもプログラミングも未経験。

## コンセプト

「スレッズの投稿もnote記事も、Claude Codeとmuseに任せる。あなたは承認するだけ」

## プリフレーム

- 誰のため：発信を始めたい、または続かない人。何を書くか、どのツールを使うかで止まっている人。
- 今の状態：ネタ出し、投稿文、記事を全部自分で悩んでいる。ツールの比較で時間が溶ける。
- なれる状態：毎日のスレッズ投稿が自動で出て、noteの記事が下書きまで仕上がる。ログが溜まり、次の商品を半分の労力で出せる。

## 役割分担（固定）

| ツール | 担当 |
|---|---|
| Claude Code | コンセプト作り、投稿・記事の企画と下書き、ログとして蓄積 |
| muse | 仮置き：スレッズへの自動投稿・運用（確認後に確定） |

## 決めてあげること（選ばせない）

- コースは1つ。期間分けも、ライト/フルのような区分もしない。
- 投稿先はスレッズ、記事はnote。他のSNSは案内しない。
- 進め方は固定の順番で、飛ばしても並べ替えてもいけない。

## やらなくていいこと

- 他のAIツールや投稿ツールの比較・検討
- ゼロからの文章作成（下書きは必ずClaude Codeが出す）
- 投稿ネタ探し
- 毎日手動で投稿ボタンを押すこと
- プログラミングの学習

## あえて受け入れてもらう不便さ（体験の核）

- 最初に必ずClaude Codeへ指示を出し、ログを残すところから始める。手でコピペして済ませる近道は教えない。
- 順番は固定。「先に投稿だけ自動化したい」は受け付けない。
- この不便さは「ログが資産になり、次の商品が半分の労力で出せる」ことの裏返しとして、最初に説明する。

## お客さんの道筋（物語形式）

**第1話　迷いの夜**
毎晩、何を投稿するかで1時間悩む。ツールを調べるほど選択肢が増え、何も始められない。「決めてくれる人がいれば」と思っている。

**第2話　1本道の宣言**
「使うのはClaude Codeとmuseだけ。順番も決まっています」と告げられる。選ばなくていい安心と、遠回りな手順への小さな戸惑いが同時にくる。

**第3話　最初の指示**
指示文をそのまま貼ると、Claude Codeが初めてコンセプトと投稿案を返す。自分で考えずに形が出たことに驚く。ログが残り始める。

**第4話　勝手に出る投稿**
museでスレッズの投稿が自動で出る。朝起きると、今日の分がもう出ている。noteの記事も下書きまで仕上がっている。

**第5話　半分の労力**
溜まったログを使い、2つ目の発信・商品を前回の半分の時間で作れる。自分の型ができたと気づく。

## 売り出し方（1つに固定）

- 発信：スレッズで、Claude Codeのログを見せながら「全人類Claude Codeを使ってください」と言い切る。
- 販売：noteで1商品のみ。プランは分けない。
- 次の段階（高単価・ファネル）は、noteが売れてから別途設計する。

## 次にやること

1. museで何ができるかの確認（役割分担表の仮置きを確定）と、あなたの実績の確認
2. このファイルをそのままClaude Codeに渡し、noteの本文とセールスの物語を作らせる
3. 第1話〜第5話をそれぞれ1投稿にしてスレッズに出す
