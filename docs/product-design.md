# 商品設計 叩き台：Claude Codeでmuse運用を仕組み化する

## 設計の原則（元投稿の要点。AIに毎回渡す）

1. お客さんに選ばせない。「AもBもCもあるので選んでください」は売れない。
2. 期間・コースで商品を分けない（3ヶ月/6ヶ月などの選択肢を作らない）。
3. 手段は1つに決めて言い切る。100%の人に正解である必要はない。例外に合わせて足すほど商品はぼやける。
4. やらなくていいことを先に決めてあげる（ダイエットの「運動はしない」と同じ）。
5. 不便さも体験の一部にする（星のや京都の「舟で行く」）。プロセスごと商品にする。
6. お客さんの権利は「Yes / No」だけ。選ぶ作業は我々が引き受ける。

## 仮置きの前提（違えば修正）

- テーマ：Claude Codeを使って、muse運用を毎日回る仕組みにする。
- 対象：muse運用を始めたい、または続かない人で、AIもプログラミングも未経験。
- 手段：Claude Code 1本。他のAIツールや手作業の併用は案内しない。
- museの位置づけ：発信チャネルとして扱う。具体的な機能や仕様は未確認で、確認後に本書へ反映する。

## コンセプト

「毎日の考える作業を、全部Claude Codeに渡す。あなたは承認するだけ」

## プリフレーム

- 誰のため：muse運用に毎日時間を取られて続かない人、何を書けばいいか分からない人。
- 今の状態：ネタ出し、下書き、改善を全部自分で悩んでいる。ツールも情報も多すぎて決められない。
- なれる状態：Claude Codeにログが溜まり、毎日の運用が決まった手順で回る。次の商品は半分の労力で出せる。

## 決めてあげること（選ばせない）

- コースは1つ。期間分けも、ライト/フルのような区分もしない。
- ツールはClaude Codeのみ。
- 進め方は固定の順番で、飛ばしても並べ替えてもいけない。

## やらなくていいこと

- 他のAIツールの比較・検討
- ゼロからの文章作成（下書きは必ずClaude Codeが出す）
- 投稿ネタ探し
- プログラミングの学習

## あえて受け入れてもらう不便さ（体験の核）

- 毎回、Claude Codeに指示を出して、ログを残すところから始める（手でコピペして済ませるショートカットは教えない）。
- 順番は固定。「先にこれだけやりたい」は受け付けない。
- この不便さは「ログが資産になる」ことの裏返しとして、最初に説明する。

## お客さんの道筋（物語形式）

**第1話　迷いの夜**
毎晩、museに何を書くかで1時間悩む。ツールを調べるほど選択肢が増えて、何も始められない。「決めてくれる人がいれば」と思っている。

**第2話　1本道の宣言**
「使うのはClaude Codeだけ。順番も決まっています」と告げられる。選ばなくていい安心と、遠回りの手順への小さな戸惑いが同時にくる。

**第3話　最初の指示**
指示文をそのまま貼って、Claude Codeが初めてコンセプトを返す。自分で考えずに形が出たことに驚く。ログが残り始める。

**第4話　日課になる**
ネタ出しから下書きまで、毎日同じ手順で10分で終わる。「今日は何を書こう」の悩みが消える。

**第5話　半分の労力**
溜まったログを使い、2つ目の発信・商品を前回の半分の時間で作れる。自分の型ができたと気づく。

## 売り出し方（1つに固定）

- 発信：Claude Codeのログを見せながら「全人類Claude Codeを使ってください」と言い切る。
- 販売：noteで1商品のみ。プランは分けない。
- 次の段階（高単価・ファネル）は、noteが売れてから別途設計する。
